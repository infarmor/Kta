## Что это

Kta снимает трафик с iPhone через USB (служба `pcapd` на телефоне, [pymobiledevice3](https://github.com/doronz88/pymobiledevice3)) и показывает по каждому приложению домены и IP-адреса.

В отличие от `rvictl`, каждый пакет сохраняется **с именем и PID процесса**. Файл `.pcapng` открывается в Wireshark.

Проверено на iOS 27 и macOS 27, на старых версиях не тестировалось.

## Установка

Нужны macOS, Python 3 и iPhone на кабеле.

```bash
git clone https://github.com/infarmor/Kta.git
cd Kta
./install.sh
```

Подключи iPhone, разблокируй его и нажми «Доверять».

## Использование

Снять 60 секунд трафика и сразу показать результат:

```bash
./kta run
```

Отдельные команды:

```bash
./kta capture --out phone.pcapng --seconds 30      # только запись (без --seconds: до Ctrl+C)
./kta capture --out pin.pcapng --process Pinterest # только одно приложение
./kta analyze phone.pcapng                          # разбор готового файла
./kta analyze phone.pcapng --process Pinterest
```

ASCII-баннер печатается в stderr. Отключить: `./kta -s run` (флаг `-s` ставится перед командой).

Пример вывода:

```
Pinterest  (2736 packets)
      1  tls api.pinterest.com
      1  tls i.pinimg.com
      4  dns graph.facebook.com
    163  quic i.pinimg.com (2.22.237.73)
```

`tls` и `quic` с именем — имя сервера из рукопожатия (TLS или первого пакета QUIC), `dns` — DNS-запрос самого приложения.
Строки с IP-адресом — пакеты QUIC и новые TCP-соединения; имя в них берётся из рукопожатия этого приложения или
из DNS-ответов в записи, а если его нет нигде, остаётся только адрес.

iOS обычно резолвит имена за приложение в системном процессе `mDNSResponder`, поэтому его DNS-ответы читаются
всегда, даже с `analyze --process`. А вот `capture --process` пишет только пакеты одного приложения, без
`mDNSResponder`: имена для IP-адресов тогда известны только из рукопожатий.

## В Wireshark

Имя процесса лежит в комментарии пакета. Фильтр:

```
frame.comment contains "ProcName: Pinterest"
```

В комментарии: `PID` и `ProcName` — процесс, `EPID` и `EProcName` — «эффективный» процесс (значение 4294967295 означает «не задан»), `SVC` — класс сервиса (QoS).

## Ограничения

- **HTTPS не расшифровывается.** Видны домены и IP, но не содержимое запросов. Для содержимого нужен прокси (Proxyman, mitmproxy), и он не работает с приложениями с SSL pinning.
- **QUIC (HTTP/3).** Имя сервера читается из первого пакета соединения (его ключи публичны, RFC 9001). Если этот пакет не попал в запись (соединение открыто до начала захвата), виден только IP или имя из DNS.
- **VPN на iPhone скрывает трафик.** Если включён VPN, приложения видны внутри туннеля как зашифрованный поток. Отключи его на время захвата.
- Часть пакетов система не привязывает к процессу, они показываются как `(unattributed)`.
- Служебный трафик между Mac и iPhone (приватные адреса `fd..`) в разбор не попадает.

## Как это устроено

1. На iPhone работает диагностическая служба `pcapd`, она видит пакеты на всех сетевых интерфейсах.
2. Mac подключается к ней через lockdown по USB (нужно доверие устройству).
3. Kta сохраняет поток в pcapng с метаданными процесса и разбирает DNS-запросы и ответы, имя сервера из TLS и QUIC (SNI) и IP-адреса назначения.

Kta подменяет в `pymobiledevice3` метод чтения пакетов, чтобы пропускать служебные кадры, которые на новых версиях iOS роняют захват с `TruncatedDataError`.
